## P1 source-free custody law before production

Classification: derived affine ownership and deliberate Bombay diagnostic policy. An attempted accepted item may discharge a receipt or retain its exact accepted value for terminal custody. Rejection, blocking, corruption, and untouched items keep their complete request. Source-free collection removes only discharged receipts and reports `Retained` for any nonempty residual; it never admits a source input. A retained accepted value remains retained on a repeated offer. In a product, a retained earlier lane does not prevent later source admission. The caller sees the existing `SourceCustody` sum and does not need a new wrapper.

The pre-edit external witness is `tests/interpreter-contract/tests/source_free_custody.rs`. It requires terminal `DiagnosticAccepted::Terminal(Box<str>)` to survive two offers, delivered diagnostics to discharge, and every source-free failure alternative to return its exact owned input. It must fail on the original unconditional `Exhausted(self)` implementation. The lower-order composition witnesses are core `source_settlement_admission`, generated creation custody, and Actors diagnostic tests; the later real Driver witness will prove continuing turns and retirement.

Aggregate-drift precheck: this edit changes no actor aggregate control state, subordinate stored state, transition branch, module, or public type. `DiagnosticAccepted` remains the accepted-value sum; the current diagnostic payload is needed at retirement only in its `Terminal` variant. The core vector is an ordered residual product, not an actor state machine. The proposed method owns one item-specific discharge decision, and no semantic boolean or positional caller syntax is introduced. Cross-checks: `actor-transition-algebra.md`, `atomic-runtime-settlement.md`, `behavior-layer-laws.md`, and all five normalized atomic laws. Disposition: `pass` for the pre-edit model, pending the failing external witness.

The Nix-pinned external fixture compiled on the prior design and failed all three focused tests for the intended law: terminal diagnostic returned `Exhausted`, source-free rejection/blocked/corrupt/untouched returned `Exhausted`, and 100 delivered diagnostics remained in an `Exhausted` vector instead of discharging. This is the red regression for P1. The fixture's first compilation required only a local test type annotation; no production API was changed to make the regression compile.

## P2 assignment delivery law before production

Classification: derived affine custody. An `AssignWorker<P, Job>` holds its opaque pool correlation while transferring only `EstablishedDelivery<P>` to the interpreter's existing exact-delivery capability. Acceptance returns the original held receipt. Rejection or corruption reunites the **actual** returned target and assignment with that same receipt, preserving the original move-only job and completion authority. A lower interpreter cannot receive, forge, or exchange the held receipt. Product traversal, not this item operation, decides attempted versus untouched. The user-level interpreter syntax is `request.settle(&mut delivery_capability).await`, with no wrapper-depth argument; source settlement later returns the resulting item settlement to the pool. This does not promise worker completion merely because delivery was accepted.

The first focused witness will construct two real issued assignments inside the pool assignment owner, transfer each through a concrete exact-delivery interpreter, reject one after observing its move-only payload, accept the other in the opposite order, and prove the exact payload, endpoint, and original correlations remain paired. This test must fail to compile before the consuming `settle` method exists. The external fixture must then obtain a request from a real FIFO transition and exercise the same public syntax and rejection, plus compile-fail privacy and double-settlement cases. Existing lower-order pieces are `EstablishedDelivery`, `InterpretItem`, `ItemSettlement`, `AssignmentSequence`, `AssignWorker`, and `SourceAction`; no new public request or generic envelope is authorized. The sole candidate production owner is `atomic/pool/assignment.rs`, forecast about +45/-25 lines before narrowing; application constructors and generic pool bounds do not change. The current `receipt` and `into_parts` methods remain only until the real external witness succeeds, after which their callers migrate mechanically and the assembly surface is removed.

Aggregate-drift precheck: FIFO control states remain unchanged. `AssignWorker` remains the single request product; its currently held target, assignment, and receipt are all required for the next settlement or exact rejection. `ItemSettlement` remains the four-alternative result, and `AssignmentDelivery` remains the pool's current delivery state. Cross-check `actor-transition-algebra.md`, `atomic-runtime-settlement.md`, `atomic-actor-features.md`, and normalized atomic ownership documents before retention. Disposition: `pass` for the proposed direct owner operation, pending the red witness.

The existing `receipt` and `into_parts` methods are legitimate inside the owning atomic module and legacy tests, but are not part of the truthful external port. The public syntax remains the consuming `settle` call, which also cannot be called twice on one request.
